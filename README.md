世界新闻沿用五回合市场周期，提前公开下一次租金乘数。现有存档和房间继续保持旧规则，新玩法只在新局启用。

## 远程多人联机

点击“远程联机”，创建 2–4 人房间并分享房间码或邀请链接。朋友加入、点击准备，由房主开始。联机模式支持八张主题地图、地产建设、抵押赎回、拍卖、现金收购和市场事件。

- 服务器统一掷骰与结算，客户端只发送操作意图；校验轮次、业主、金额与卖方确认。
- 每两秒同步房间状态。操作带版本号和唯一编号，重复请求不会重复扣款或掷骰。
- 刷新同一页自动恢复座位；也可以从“恢复已保存的座位”重连。邀请链接仅含房间码，座位凭证单独保存在浏览器。不同设备作为不同玩家加入。
- 单阶段等待 180 秒后，服务器自动掷骰、放弃购买/竞价、拒绝交易或结束回合，欠款时优先清算资产。
- 房间进度持久化到服务器，正常服务重启后可恢复。等待房间最后一次变更后保留 24 小时，已开局/结束房间最后一次操作后保留 7 天。当前版本最多 100 个保留房间。
- 本地 AI 对局、5 个手动存档、上一局备份与 JSON 导入导出继续保留，联机进度独立保存。

## 开发与验证

Node.js 20，无第三方依赖。

    node verify.cjs
    node verify-online.cjs
    node server/server.cjs

前端位于 tycoon/，后端位于 server/。服务默认只监听 127.0.0.1:8912，通过同源 /tycoon/api/ 反向代理提供房间接口。生产环境必须使用 HTTPS。

verify.cjs 包含 35 项原有游戏检查；verify-online.cjs 包含 31 项房间授权、同步结算、请求去重、存储回滚、重启恢复与 HTTP 接口检查。

## 部署

仓库提供本次宝塔环境对应的 deploy.sh、Nginx 片段与 systemd 服务。部署前检查脚本中的域名、Node 路径和端口是否符合你的服务器。

    bash deploy.sh prepare
    # 验证 /tycoon-v4/ 后切换正式目录
    bash deploy.sh publish

后端程序安装至 /www/tycoon-online/app-v4，房间数据由 www 服务账户保存在 /var/lib/tycoon-online，位于网站根目录之外。上线前会备份旧前端；Nginx 通过独立扩展配置增加 API 路由。主站其他页面保持原有路由。
